\addcontentsline{toc}{section}{Appendix F: Extended Sponsor Activity Code}
% ======================================================================

This appendix documents the extended code generated for the Sponsor-directed
autonomous control layer, covering agent coordination protocols, safety
escalation workflows, analytics dashboards, and integration with the existing

\subsection*{F.1 Agent Coordination Protocols}

Three coordination protocol scripts implement the inter-agent communication
patterns described in the main sections of this paper.

\textbf{Event Bus} (\texttt{agent\_event\_bus.py}): Implements a
publish-subscribe event bus supporting seven event types
(GATE\_TRANSITION, SAFETY\_ALERT, ENROLLMENT\_UPDATE, ROBOT\_STATUS,
DATA\_QUALITY, REGULATORY\_DEADLINE, VENDOR\_PERFORMANCE). Each event
carries a timestamp, source agent identifier, severity level (1-5), and
a structured payload dictionary. The bus routes events to subscribed
agents based on event type with priority ordering.

\textbf{Escalation Engine} (\texttt{escalation\_engine.py}): Implements
the five-level escalation model from Level 1 (Informational, auto-logged)
through Level 5 (Safety-critical, mandatory human with no timeout). The
engine evaluates decision context, confidence scores, and decision types to
determine the appropriate escalation level, required approvals, and timeout
settings for each sponsor decision.

\textbf{Gate Transition Manager} (\texttt{gate\_transition\_manager.py}):
Implements the seven-gate decision framework with go-criteria evaluation,
KPI score computation, and gate outcome determination (advance, conditional
advance, hold, or terminate). Each gate transition generates a structured
decision record with rationale and recommended next actions.

\subsection*{F.2 Safety Escalation Workflows}

Three safety workflow scripts implement the robotic procedure safety
monitoring architecture.

\textbf{Robotic Safety Workflow} (\texttt{robotic\_safety\_workflow.py}):
Implements the four-category safety event classification system:
Category A (no deviation, log and archive), Category B (minor deviation,
increase monitoring), Category C (significant deviation, pause and notify
clinician), and Category D (critical event, immediate halt with emergency
protocol activation). Processes robot telemetry including force, position,
and communication status data.

\textbf{Procedure Authorization} (\texttt{procedure\_authorization.py}):
Implements the four-gate safety gate protocol for robotic procedures.
Gate 1 verifies patient consent and identity. Gate 2 confirms system
readiness including calibration and instrument status. Gate 3 validates
procedure parameters against safety envelopes and digital twin
predictions. Gate 4 obtains clinical authorization for Tier 2 and
Tier 3 procedures requiring clinician or mandatory human sign-off.

\textbf{Telemetry Monitor} (\texttt{telemetry\_monitor.py}):
Provides continuous telemetry monitoring with category-specific
thresholds for all 10 robot types. Implements graduated alarm levels
(advisory, caution, halt) for force/torque, position deviation, and
communication latency parameters.

\subsection*{F.3 Analytics Dashboard and Reporting}

\textbf{Sponsor Dashboard} (\texttt{sponsor\_dashboard.py}): Terminal-based
analytics display showing active agent status, decision queues, escalation
pipeline, robot authorization status, patient flow metrics, and PSL score
trends. Operates without external GUI dependencies using pure terminal
output formatting.

\textbf{Report Generator} (\texttt{report\_generator.py}): Produces
formatted markdown reports covering hourly summaries, daily summaries,
agent performance metrics, safety event logs, escalation audit trails,
and robot utilization statistics. Reports are output to
\texttt{scripts/output/reports/} with embedded text tables.
